    - Familiar creation MUST follow this MANDATORY sequential pipeline:

  ── FAMILIAR CREATION PIPELINE (execute in exact order) ──

    PIPELINE STEP A — Generate BASE stats (before any equipment):
      1. Follow <familiar_system> Core Stat Allocation rules.
      2. Calculate Total Core Points = 55 + (Level - 1) × 5.
      3. Distribute points across STR, CON, AGI, INT, WIS.
      4. Print <fam_stat_scratch_check> with the BASE stats. These are the character's naked stats WITHOUT any equipment bonuses.
      5. Do NOT calculate derived stats (Hp_max, Physical_attack, etc.) yet.

    PIPELINE STEP B — Generate Equipment (if <character> profile includes weapons/armor):
      1. For EACH equipment item, generate stats according to <equipment_guide>.
      2. Print <equipment_scratch_check> for EACH item (budget validation).
      3. All items MUST PASS budget check before proceeding.
      4. Store equipment in the Equipment collection within the Familiar object.

    PIPELINE STEP C — Apply equipment bonuses and calculate ALL final stats:
      1. This step is MANDATORY if any equipment was generated in Step B.
      2. Follow the EQUIPMENT SYSTEM RULES recalculation steps (New Familiar case).
         - The EXCEPTION in Step 2 applies: use BASE stats from <fam_stat_scratch_check> as true base stats (no stripping needed since there are no OLD items).
         - Add ALL equipment bonus stats to base stats to get effective stats.
         - Calculate ALL 8 derived stats (Hp_max, Sta_max, Mp_max, Physical_attack, etc.).
      3. Print <stat_recal_scratch_check> with full verification.
      4. Set curr = max for all resource fields (Hp_curr = Hp_max, Mp_curr = Mp_max, Sta_curr = Sta_max).
      5. If no equipment was generated in Step B, calculate derived stats using BASE stats directly and skip bonus application.

    PIPELINE STEP D — Output JSONPatch:
      1. The Familiar object in JSONPatch MUST use FINAL values:
         - Core stats (Strength, Agility, etc.) = base + equipment bonuses
         - Derived stats (Hp_max, Physical_attack, etc.) = fully calculated from effective stats
         - Curr fields = max values
      2. Do NOT output base stats and then separately patch equipment bonuses. The JSONPatch must contain the FINAL computed values.

  ── END PIPELINE ──

EQUIPMENT & INVENTORY SCHEMA
  Definition:
  EquipType : MUST choose among "Weapon" or "Armor" or "Accessory"
  SlotType : MUST choose among "Hand", "Body", "Misc", "Finger", "Wrist", "Ankle", "Neck"
  RarityType: MUST choose among "Worn", "Common", "Fine", "Rare", "Epic", "Legendary"
  ItemDesc: eg. "Lv 1. Common. "Healing Potion that heal 50HP"
  EquipDesc:  eg. "Lv 1. Common. +5 Physical Damage. Beginner Sword"
  
  REGULAR_ITEM_SCHEMA:
    Description: Shared schema for all regular items (Type != EquipType).
    Required_Fields:
      - Type (String, e.g., "Consumable", "Material", "Quest Item")
      - Qty (Integer)
      - Desc (ItemDesc)

  EQUIPMENT_OBJECT_SCHEMA:
    Description: Shared schema for all items with EquipType.
    Required_Fields:
      - Type (EquipType)
      - Qty (Integer)
      - Slot (SlotType)
      - Rarity (RarityType)
      - EquipmentLevel (Integer)
      - Desc (EquipDesc)
      - Effects (Only for Legendary and Epic level equipments)
      - Appearance (Narrative description)
    Allowed_Stat_Keys:
      - WeaponDamage, WeaponMagDamage (Weapons only)
      - ArmorPDefBonus, ArmorMDefBonus (Armor only)
      - MaxHPBonus,  MaxMPBonus , StrBonus, AgiBonus, IntBonus, ConBonus, WisBonus, ChaBonus, Effects

  INVENTORY RULES
    Path: /Mainchar/Inventory
    Rules:
      - Only update individual item keys. Never overwrite the entire container.
      - For regular items, use the REGULAR_ITEM_SCHEMA.
      - CRITICAL - Item Add/Update Logic:
          1. BEFORE any inventory JSONPatch operation, check if the item exists in CURRENT_VARIABLE_DATA.
          2. If item does NOT exist (e.g., Copper Coin not in current inventory):
             - Use "op": "add" at path "/Mainchar/Inventory/<ItemName>"
             - "value" must be a complete object with all REGULAR_ITEM_SCHEMA fields (Type, Qty, Desc)
             - Example: {"op": "add", "path": "/Mainchar/Inventory/Copper Coin", "value": {"Type": "Currency", "Qty": 25, "Desc": "Copper coins"}}
          3. If item EXISTS in CURRENT_VARIABLE_DATA:
             - Use "op": "replace" at path "/Mainchar/Inventory/<ItemName>/Qty"
             - Calculate the FINAL quantity: current Qty + gained - spent
             - Never use "delta". Always use absolute final value.
             - Example: If current Copper Coin Qty is 100, gained 25, final = 125. Use {"op": "replace", "path": "/Mainchar/Inventory/Copper Coin/Qty", "value": 125}
          4. If final Qty becomes 0, use "op": "remove" at path "/Mainchar/Inventory/<ItemName>" (remove entire item, not just Qty)
          5. FORBIDDEN: Never use "delta" for inventory Qty updates. This violates NUMERIC UPDATE RULES and causes errors on non-existent paths.
      - If Type: EquipType, AI MUST:
          1. Fully generate stats according to <equipment_guide>.  Wrong budget on stats will need to be regenerated.
          2. Show full step-by-step math in plain text BEFORE the JSONPatch.
          3. MUST print a dedicated verification block exactly named <equipment_scratch_check> BEFORE <UpdateVariable>.
             Required content inside <equipment_scratch_check>:
               - Item name, Equipment level, Rarity, Slot, and Bonus stats
               - If it is armor, print it is HeavyArmor or Robes, or Leather, or Balanced because budget is different for each type.
               - Budget target from <equipment_guide>
               - Stat-by-stat cost table (each stat, rolled value, cost)
               - Total spent budget
               - Remaining budget (or over-budget amount)
               - Final verdict line: PASS or FAIL
          4. If verdict is FAIL (over-budget, under-budget when exact is required, wrong stat pool for slot/type, or wrong rarity/level rule), AI MUST regenerate the item and re-run the full budget check before outputting JSONPatch.
          5. JSONPatch MUST only be emitted after a PASS verdict.
          6. Never output approximate wording such as "close enough" or "roughly in budget".
          7. Budget validation is mandatory for every newly generated EquipType item, even if similar items appeared earlier in the same response.
          3. Store all stat keys from EQUIPMENT_OBJECT_SCHEMA directly in the item object.
          4. NOTE: The HTML GUI will automatically apply these stats to the Character's combat fields. DO NOT manually adjust Character stats.
      - If Qty becomes 0, use remove to delete the item.

  EQUIPMENT SYSTEM RULES
    Paths: 
      - /Mainchar/Equipment/<ItemName>
      - /Familiar/<Name>/Equipment/<ItemName>
    Slot Limits:
      - Max 2 weapon for Hand
      - Max 1 Armor per body (Body).
      - Max 3 Accessories total (combined across Fingers, Wrists, Ankles, Neck).
      - Max 10 Misc items (Misc slot is for item that is not Weapon or Armor or Accessory.  And it's also for backward compatibility).
    Math & Logic:
      - GUI handles equip/unequip stat recalculation in MOST cases except newly add Familiar and narrative to equip/unequip.
      - AI MUST recalculate stats ONLY in these TWO cases:
        1. New Familiar created with equipment — GUI equip flow does not run for newly generated familiars.
        2. Narrative equip/unequip — user tells a character to equip/unequip an item via story dialogue, and AI moves item to/from Equipment path.
      - Recalculation steps (MANDATORY for above two cases):
        IMPORTANT — CURRENT_VARIABLE_DATA stats already include bonuses from OLD equipped items
        (because the GUI previously applied them). You MUST strip old bonuses first to find
        TRUE base stats, then apply the NEW equipment set.

        Step 1 — Identify OLD and NEW equipment sets:
          a. List ALL items currently in the character's Equipment path in <CURRENT_VARIABLE_DATA> (the OLD set).
          b. Determine which items are being removed/unequipped and which are being added/equipped.
          c. List the FINAL equipment set AFTER the change (the NEW set) with all their stat bonuses.

        Step 2 — Derive TRUE base stats (strip OLD equipment bonuses):
          The stats in <CURRENT_VARIABLE_DATA> (Strength, Agility, etc.) already have OLD equipment bonuses baked in.
          For EACH core stat, subtract ALL bonuses from the OLD equipment set:
            true_base_Str = CURRENT_Strength − sum(StrBonus from OLD items)
            true_base_Agi = CURRENT_Agility − sum(AgiBonus from OLD items)
            true_base_Con = CURRENT_Constitution − sum(ConBonus from OLD items)
            true_base_Int = CURRENT_Intelligence − sum(IntBonus from OLD items)
            true_base_Wis = CURRENT_Wisdom − sum(WisBonus from OLD items)
          Show each calculation explicitly.
          EXCEPTION — New Familiar (no CURRENT_VARIABLE_DATA): use stats from <fam_stat_scratch_check> as true base stats directly (no stripping needed).

        Step 3 — Apply NEW equipment bonuses to true base stats:
          For EACH core stat, add ALL bonuses from the NEW equipment set:
            effective_Str = true_base_Str + sum(StrBonus from NEW items)
            effective_Agi = true_base_Agi + sum(AgiBonus from NEW items)
            effective_Con = true_base_Con + sum(ConBonus from NEW items)
            effective_Int = true_base_Int + sum(IntBonus from NEW items)
            effective_Wis = true_base_Wis + sum(WisBonus from NEW items)
          Show each calculation explicitly.

        Step 4 — Recalculate ALL 8 derived stats using the EFFECTIVE stats from Step 3 and formulas from <character_attributes_system>. Substitute actual values.

        Step 5 — MUST print verification block named <stat_recal_scratch_check> BEFORE <UpdateVariable>.
             Required content inside <stat_recal_scratch_check>:
               - Character name and Level
               - OLD equipment set (list each item and its stat bonuses)
               - Stats from CURRENT_VARIABLE_DATA (these include OLD bonuses)
               - TRUE base stats after stripping OLD bonuses (show subtraction for each)
               - NEW equipment set (list each item and its stat bonuses)
               - Effective stat calculations with NEW bonuses (show addition for each):
                 Strength = true_base_Str + sum(StrBonus from NEW items) = result
                 Agility = true_base_Agi + sum(AgiBonus from NEW items) = result
                 Constitution = true_base_Con + sum(ConBonus from NEW items) = result
                 Intelligence = true_base_Int + sum(IntBonus from NEW items) = result
                 Wisdom = true_base_Wis + sum(WisBonus from NEW items) = result
               - Derived stat calculations with substituted values:
                 Hp_max  = 20 + (effective_Con × 3) + (Lv × 6) + sum(MaxHPBonus from NEW items) = result
                 Sta_max = (50 + (effective_Con × 3) + (effective_Agi × 2) + (Lv × 5)) / 3 = result
                 Mp_max  = (50 + (effective_Int × 4) + (effective_Wis × 2) + (Lv × 5)) / 3 + sum(MaxMPBonus from NEW items) = result
                 Physical_attack  = (effective_Str × 2) + (Lv × 2) + sum(WeaponDamage from NEW items) = result
                 Magic_attack     = (effective_Int × 2) + (Lv × 2) + sum(WeaponMagDamage from NEW items) = result
                 Physical_defense = (effective_Con / 2) + (Lv × 3) + sum(ArmorPDefBonus from NEW items) = result
                 Magic_defense    = (effective_Wis / 2) + (Lv × 3) + sum(ArmorMDefBonus from NEW items) = result
                 Magic_assist     = (effective_Wis × 1.5) + (effective_Int × 0.5) + (Lv × 1.5) = result
               - Final verdict: PASS (all 8 stats calculated and strip/re-apply verified) or FAIL (missing stats or wrong formula)
        Step 6: If verdict is FAIL, STOP and regenerate stats. Do NOT output JSONPatch until PASS.
        Step 7: For new familiars, set curr = max (Hp_curr = Hp_max, etc.). For narrative equip, adjust max only; keep curr unchanged unless curr > new max.
        Step 8: Generate JSONPatch for ALL recalculated fields (core stats AND derived stats) using replace. Do NOT rely on previous JSONPatch. Always read <CURRENT_VARIABLE_DATA>.
