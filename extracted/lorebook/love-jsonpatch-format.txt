    - If the JSONPatch format is not having the exact syntax below, AI is required to re-generate.
	- TUPLE FIELD RULES
		  Description:
			Many fields are stored as tuples in the form [value,label].
		  check:
			- When updating only the actual value of a tuple field, ALWAYS target index /0.
			- Never replace the whole tuple unless explicitly changing both the value and the label.
			- Never change index /1 unless explicitly instructed to change the label.
			- Common tuple examples include:
			  - /Mainchar/Charisma/0
			  - /Mainchar/Energy_curr/0
			  - /Mainchar/Money/0
			  - /Partner/<NameKey>/Affection/0
			  - /Partner/<NameKey>/Trust/0
			  - /Partner/<NameKey>/Comfort/0
			  - /Partner/<NameKey>/Arousal/0
			  - /Partner/<NameKey>/Mood/0        (string tuple — value is a text string e.g. "Happy")
			  - /Partner/<NameKey>/RelationshipStage/0  (string tuple)
			  - /Partner/<NameKey>/ConflictActive/0     (boolean tuple — value is true or false, NOT bare boolean)
			  - /Partner/<NameKey>/Is_present/0         (boolean tuple — value is true or false, NOT bare boolean)
			- If CURRENT_VARIABLE_DATA shows a field as [x,"label"], the patch path for value updates MUST use /0.
			- BOOLEAN TUPLES: ConflictActive and Is_present are stored as [boolean,"label"]. When creating a Partner, these MUST be tuples e.g. [false,"Conflict Active"], NEVER bare true/false.
